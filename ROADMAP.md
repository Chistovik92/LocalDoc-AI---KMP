# План версий

Единственный источник **будущих** планов проекта. Выпущенное и исправленное записывается в
[CHANGELOG.md](CHANGELOG.md), правила разработки — в [AGENTS.md](AGENTS.md). Новый пункт попадает сюда сразу,
как только появился; при релизе раздел версии удаляется отсюда, а его итог остаётся только в CHANGELOG —
так история не дублируется.

Статусы версий: **в разработке** · **план**. Последняя выпущенная версия — 2.4.2.

Дорожная карта: 2.4.0 → 2.5.0 → … → 2.8.0, затем большие проекты **3.0.0** и **4.0.0**.
Версии 2.x — проверка на устройствах, доводка и то, что требует аккаунтов; два больших проекта, которые не помещаются
в минорные версии, вынесены в 3.0.0 и 4.0.0.

## 2.4.3 — исправления чтения, PDF и перевода · план

Три дефекта с устройств после 2.4.2. У каждого — сначала воспроизведение и причина (сейчас это
гипотезы по коду), потом правка, потом проверка. Порядок работ: 1 → 3 → 2 (см. «Порядок» в конце).

### 1. Постраничное чтение: последняя строка обрезается на границе страницы (веб, «постранично»)

Симптом: в режиме «постранично» низ страницы обрезает строку по глифу (метка «10 из 15»), прокрутки нет,
дочитать строку нельзя. Отдельно: номер страницы и ползунок в веб-режиме ведут себя неровно («~» в числе,
ползунок откатывается).

Причина (подтвердить): `ScreenPager` резервирует высоту страницы по сумме высот строк от `TextMeasurer`
(`getLineBottom − getLineTop`), а `BlockText` рисует каждый кусок отдельным `Text` — с padding шрифта
(`includeFontPadding`), округлением dp→px и своим верхним/нижним довеском абзаца. Довесок не зарезервирован,
`clipToBounds` в `ScreenPageContent` срезает его по живому глифу.

- [x] `ComposePageMeasurer` (`ReaderTypography.kt`): учитывать довески абзаца, которых нет в сумме строк, — `layout.size.height − Σ(getLineBottom − getLineTop)` (правка: весь довесок складывается в `BlockMeasure.bottom`, а не по сторонам: резерв нижней строки и есть то место, где резалось)
- [x] Одинаковая ширина: `pageContentWidthPx` считать как `min(area, 720.dp) − margin.dp − margin.dp` с `roundToPx()` (сейчас `(margin * 2).dp.toPx()` после округления даёт ширину на 1–2 px больше реальной), измерять ровно этой `Int`-шириной
- [ ] Одинаковая высокая строка: `includeFontPadding = false` и явный `LineHeightStyle` в `blockBaseStyle`/`blockTextStyle` — один стиль и для измерения, и для отрисовки *← отменено: риск сломать вёрстку везде; покрывает запас ниже*
- [x] Запас страницы: `PAGE_SAFETY_DP` (4 dp) вычитать из высоты области в `ScreenPageContent` перед `PageSpec` — любая оставшаяся погрешность не режет глиф; самопроверка `onSizeChanged` пишет в лог, если отрисованная страница всё же выше бюджета
- [x] `PageBar` перекрывает низ страницы: *отклонено от плана* — высоту панели из области не вычитаем (дорогая перевёрстка на каждый показ панели), вместо этого `PageBar`/`PlayerBar` стали полупрозрачными (alpha 0.9), текст под панелью читается
- [x] «N из M»: не показывать «~», когда глава читателя разложена; пока раскладка идёт — строка «N из …» (`page_of_incomplete`, 5 локалей)
- [x] `PageBar` в постраничном режиме: ползунок активен только при `screenLayout.isComplete` (`seekEnabled`), не забрасывает на ближайшую готовую страницу
- [ ] Границы чтения в веб-режиме: проверить, что листание тапом/свайпом и `chapterButtons` (`pagedListing`) не конфликтуют с `PageBar` и что номер страницы не меняется при включении/выключении перевода
- [ ] Проверка: `ScreenPagerTest` — инвариант «Σ высот строк + довески ≤ высота страницы»; на устройстве веб-глава × {3 размера шрифта, 2 темы, поворот}: последняя строка каждой страницы видна целиком, номер страницы точный

### 2. PDF не читается: вместо страницы иконка «битой картинки», счётчик «1 / 1»

Симптом: книга-PDF открывается как страницы-картинки, но вместо страницы белая иконка `BrokenImage`,
счётчик «1 / 1». Текстовый режим при этом есть (кнопка `TextFields`).

Причина (подтвердить, три кандидата): (а) `PdfPageSource.page()` глотает `runCatching` и **отмену** тоже —
любой свайп/пересоздание `LaunchedEffect` навсегда ставит `failed`; (б) `decodeImageBitmap` вернул null (OOM:
двойной пик «bitmap → JPEG → bitmap» на ARGB_8888 при `MAX_RENDER_WIDTH = 2200`); (в) `PdfRenderer.render`
бросил на шифрованном/битом файле или копия не та, что разбиралась (отсюда «1 из 1»).

- [x] `PdfPageSource.page()`: не глотать отмену — явный `try/catch` с `throw e` для `CancellationException`; отдавать результат с причиной (`Ok(bytes)` / `Failed(reason)`), а не `null` *(сделано: sealed `PdfPageResult.Ready/Failed`)*
- [x] `PdfPageView`: вместо иконки — текст причины, «Повторить» и «Текстовый режим»; `failed` сбрасывать по кнопке и никогда не ставить при отмене *(повтор — перевзвод запроса `attempt++`)*
- [x] Открытие документа: проверить копию (`files.sizeOf(book.pdfFile)`), при отсутствии/нуле — сообщение «Копия PDF не найдена, открыт текст» и `onShowText()`; сверить `pageCount` копии с числом страниц текстового слоя и предупредить при расхождении *(сделана проверка `sizeOf` при открытии; сверка `pageCount` — см. пункт «диагностика» ниже)*
- [x] Память: `RENDER_OVERSAMPLE` 1.5 → 1.25, `MAX_RENDER_WIDTH` от `Runtime.maxMemory()`, `PdfRenderSize.MAX_PIXELS` 6M → 3M; PDF-страницу декодировать в `RGB_565` (параметр в `decodeImageBitmap`) — уходит двойной пик *(сделано: `preferRgb565` в `decodeImageBitmap`, на iOS игнорируется)*
- [ ] Кэш: держать готовые `ImageBitmap` с лимитом по байтам вместо JPEG-байтов с повторным декодированием (или снизить `DEFAULT_CACHE_BYTES`) *← частично покрыто RGB_565; перенос в 2.5.0*
- [x] Диагностика: писать в лог причину сбоя `PdfPageRenderer.render` (шифрование, битый файл, OOM) — сейчас сбой виден только иконкой
- [ ] Автофоллбэк: после 2–3 неудачных страниц подряд предлагать текстовый режим баннером, а не по одной иконке на страницу *← перенос в 2.5.0*
- [ ] Проверка: `PdfPagesTest` — отмена не даёт `Failed`, кэш не растёт сверх лимита, `PdfRenderSize.fit` держит `MAX_PIXELS`/`MAX_SIDE`; на устройстве — текстовый, сканированный и большой (300+ страниц) PDF, быстрое листание, поворот, профиль памяти *(тесты обновлены под `PdfPageResult`; прогон на устройстве — перед выпуском)*

### 3. Перевод веб-страницы сломан при локальной модели

Симптом: при `preferPageTranslation = false` (перевод «своей» моделью) перевод веб-страницы не доходит до
конца: прогресс дёргается, страница остаётся в оригинале, иногда ошибка. С Google-переводчиком работает.

Причина (подтвердить): локальная модель переводит страницу десятки секунд, а `ReaderView` на каждом листании
зовёт `retainOnly(setOf(pageKey, nextKey))` — покинутая страница отменяется вместе с прогрессом
(`finally { _progress − key }`). Плюс `translatePage` держит `gate` на всю страницу, поэтому предзагрузка
соседней встаёт поперёк текущей; в последовательной ветке сбой одного блока рушит всю страницу;
`LaunchedEffect` не перезапускается при смене переводчика; без загруженной модели `check(engine.isLoaded())`
даёт ошибку вместо Google или предложения загрузить модель.

- [x] `PageTranslator`: частичный прогресс страницы хранить отдельно от job (`partials`) и не терять при отмене; `request` продолжает с уже переведённых блоков (в тесте число вызовов `translateText` не растёт)
- [x] `retainOnly(keep)` → `cancelFar(keep, radius = 2)`: отменять только далёкие страницы без прогресса; странице, которую читатель только что покинул, дать дожить до конца *(сделано с `radius = 1`: занятая страница — где есть хоть один переведённый блок — не отменяется в любом случае; больший радиус лишь держал бы лишние простаивающие job)*
- [x] `gate` на всю страницу → мьютекс на один блок + приоритет: блоки текущей страницы раньше предзагрузки следующей *(приоритет — эффект в `ReaderView` ждёт текущую страницу, прежде чем готовить соседнюю)*
- [x] В последовательной ветке ловить сбой блока (`runCatching`), оставлять оригинал и показывать «переведено X из Y» *(сбой первого блока по-прежнему роняет страницу — иначе «ошибка модели» стала бы молчаливым оригиналом; частично переведённая страница не пишется в стор и потом доканчивается)*
- [x] Добавить `pageTranslator` в ключи эффекта перевода и отменять job другого переводчика для этого документа при переключении настройки *(через `cancelDoc`)*
- [ ] Модель не загружена: для `web:` предпочитать Google-переводчик, если сеть есть, и показывать баннер с кнопками «Google-перевод» / «Загрузить модель»; локальную модель оставить для офлайна *← перенос в 2.5.0*
- [ ] Понятный прогресс: подсказка «перевод локальной моделью идёт медленно» при `parallelBlocks == 1`, чтобы ожидание не выглядело зависанием *← перенос в 2.5.0*
- [ ] Проверка: новый `PageTranslatorTest` с медленным фейковым переводчиком — листание не отменяет текущую страницу, частичный прогресс переживает отмену и не переводит заново, сбой блока не рушит страницу, `cancelFar` не трогает соседние; на устройстве — веб-глава с локальной моделью, быстрое листание туда-обратно, баннер доходит до «N из N» *(тесты написаны и зелёные, включая `cancelFar` на механике hold/release; на устройстве — перед выпуском)*

Порядок: 1 (вёрстка — видно на каждой странице) → 3 (сломанная функция) → 2 (PDF: сначала лог причины,
потом правки, чтобы не чинить гипотезу). Каждый шаг — отдельный коммит в ветке `release-2.4.3`; CHANGELOG и
`.github/release-notes.md` — при выпуске, не сейчас.
