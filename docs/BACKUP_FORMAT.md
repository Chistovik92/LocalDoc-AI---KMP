# Формат резервной копии и синхронизации LocalDoc AI

Версия документа: **2** (формат копии 2, формат синхронизации 1, схема хранилища 1). С выходом 2.0.0 формат
заморожен: менять его можно только увеличением версии и с чтением всех прежних версий.

Реализация: `backup/Backup.kt`, `backup/BackupSchedule.kt`, `sync/*`, `storage/StorageMigrations.kt`.

## 1. Резервная копия (`.ldbackup`)

ZIP-архив (UTF-8 имена). Файлы внутри сжимаются Deflate (метод 8), если это уменьшает размер, иначе хранятся
без сжатия (метод 0). Читатель обязан понимать оба метода.

| Запись в архиве | Содержимое |
| --- | --- |
| `backup.json` | manifest (ниже) |
| `kv/<ключ>` | значение настройки как есть (JSON-строка), ключи из списка ниже |
| `files/<имя>` | файлы книг: `<id>.json` (разобранная книга) и `<id>.img.<имя>` (картинки) |

manifest:

```json
{
  "format": "localdoc-backup",
  "version": 2,
  "appVersion": "2.0.0",
  "createdAt": 1700000000000,
  "books": 12,
  "keys": ["library_v1", "bookmarks_v1"],
  "files": ["a1.json", "a1.img.im0"],
  "schema": 1
}
```

- `version` — версия формата архива. Приложение читает свою и более старые версии; более новую отклоняет
  сообщением «обновите приложение», ничего не меняя.
- `schema` — версия схемы хранилища (раздел 3) на момент копии; у копий версии 1 поля нет (читается как 0).
- `createdAt` — миллисекунды Unix-эпохи (UTC).
- Ключи `kv/…`: `library_v1`, `bookmarks_v1`, `annotations_v1`, `dictionary_v1`, `reader_settings`,
  `voice_settings`, `translation_settings`; необязательный `reading_stats_v1` (статистика чтения: `days` по `ГГГГ-ММ-ДД` с `ms` и `words`, `books`) — копии без него читаются как есть.
- **Никогда не входят:** пароли и cookie сайтов (защищённое хранилище), пароли шифрования и синхронизации,
  скачанные модели и голоса, кэш картинок, поисковый индекс, состояние синхронизации, расписание копий.
- Имена файлов — простые (`[A-Za-z0-9][A-Za-z0-9._-]*`, без `..`): защита от выхода из папки приложения.

История версий формата копии:

| Версия | Что изменилось |
| --- | --- |
| 1 | ZIP без сжатия (1.5–1.9) |
| 2 | Deflate при записи, поле `schema` в manifest (2.0.0) |

**Восстановление.** Файл проверяется целиком (формат, версия, все записи, текст каждой книги разбирается) до
первой записи; при ошибке данные приложения не тронуты. После записи сбрасывается отметка схемы и запускаются
миграции хранилища (раздел 3), поэтому копии версии 1 и любой схемы приводятся к текущей.

**Копия по расписанию.** При запуске приложения, если с прошлой копии прошло заданное число дней
(`backup_schedule`: `enabled`, `everyDays` 1–365, `keep` 1–30), создаётся `autobackup-<YYYY-MM-DD>.ldbackup` в
хранилище приложения; лишние старые копии удаляются. Это обычные копии формата выше.

## 2. Синхронизация

Один зашифрованный файл `localdoc-sync.ldsync` в облаке (WebDAV; iCloud и Google Drive — через тот же интерфейс
транспорта `SyncTransport`, платформенные реализации пока заготовки).

### 2.1 Конверт шифрования

```
"LDSY" | версия(1) = 1 | KDF(1) = 1 | итерации(4, big-endian) | соль(16) | IV(12) | шифртекст | тег(16)
```

- KDF 1 — PBKDF2-HMAC-SHA256, 600 000 итераций (читается 1 000…5 000 000), ключ 256 бит.
- Шифр — AES-256-GCM; заголовок (первые 26 байт) подписывается как дополнительные данные.
- Новая соль и IV при каждой записи. Пароль в облако не попадает и нигде не сохраняется, кроме защищённого
  хранилища устройства.

### 2.2 Документ (после расшифровки — JSON)

```json
{
  "format": "localdoc-sync",
  "version": 1,
  "revision": 17,
  "writtenBy": "a1b2c3",
  "writtenAt": 1700000000000,
  "records": [
    {"id": "progress/9f3a…", "updatedAt": 1700000000000, "device": "a1b2c3", "deleted": false, "data": "{\"block\":42}"}
  ]
}
```

- `id` = `вид/ключ`. Виды: `progress` (ключ — ключ книги), `bookmark` и `annotation` (`ключКниги/идентификатор`),
  `shelf` (идентификатор подборки). Неизвестные виды сохраняются и пересылаются без изменений.
- Ключ книги — FNV-1a 64 от `ФОРМАТ|источник`, шестнадцатеричный: одинаков на всех устройствах; путь файла в
  документ не попадает. Книги без источника не синхронизируются.
- `data` — JSON записи без локальных идентификаторов (у закладок и цитат `entryId` пустой).
- Удаление — запись с `deleted: true` (надгробие), хранится 90 дней.
- `revision` растёт на 1 при каждой записи; меньшее значение, чем уже виденное, — откат облака.

### 2.3 Слияние

«Последняя правка по каждой записи»: побеждает больший `updatedAt`, при равенстве — больший `device`.
Локальные правки находятся сравнением данных с общей базой (состояние последней синхронизации). Конфликт
(запись изменена на обеих сторонах) записывается в журнал изменений (последние 200 строк в состоянии).

Порядок: скачать → расшифровать → слить → **отправить** (с проверкой `If-Match`/`If-None-Match`, до 3 повторов
при гонке) → применить к устройству → сохранить состояние. Обрыв связи до отправки не меняет ничего; после
отправки — следующая синхронизация повторит применение.

**Безопасный режим** (ничего не пишется, пока пользователь не выберет «слить», «оставить моё», «взять облако»):
ревизия облака меньше виденной; слияние удалило бы на устройстве больше половины записей (от 5 штук).
Перед первой записью в данные устройства делается копия `presync-backup.ldbackup`.

Записи, которым на устройстве не к чему примениться (нет книги), ждут и удалением не считаются.

## 3. Схема хранилища и миграции

Ключ `storage_schema` в KV. Нет ключа — данные любой версии 1.x. Текущая схема — **1**.

| Шаг | Что делает |
| --- | --- |
| 0 → 1 | Списки (`library_v1`, `bookmarks_v1`, `annotations_v1`) читаются по элементам: нечитаемый элемент отбрасывается, остальные остаются; настройки читалки, озвучки и перевода сохраняют читаемые поля. Прежнее значение изменённого ключа — в `migration_backup_<ключ>`. Нечитаемое целиком значение не трогается |

Данные схемы новее поддерживаемой не меняются. Миграции идемпотентны.
