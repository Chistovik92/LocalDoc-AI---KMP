# Аудит безопасности 2.0.0

Статический аудит кода ветки `release/2.0.0` (Android и общий код; iOS — по исходникам, без запуска). Предыдущий
аудит устойчивости разбора файлов был в 1.7.5 (`RobustnessTest`). Здесь — всё, что появилось позже, и
повторная проверка основных границ доверия.

Степень риска: **высокая** — удалённо эксплуатируется без участия пользователя; **средняя** — нужен хитрый
сервер/файл или действие пользователя; **низкая** — ограниченный ущерб или нужен физический доступ.
Статус: **исправлено** (с тестом), **принято** (осознанное решение), **открыто** (записано в ROADMAP.md).

## Подробности

### Секреты — проверено, замечаний нет

- Пароли сайтов, cookie сессий, пароль WebDAV и пароль шифрования синхронизации лежат в `SecureStore`:
  Android — AES-256-GCM, ключ в Android Keystore (не покидает хранилище); iOS — Keychain с
  `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (без iCloud и резервных копий устройства).
- В обычном `KeyValueStore` (SharedPreferences / NSUserDefaults) секретов нет: там только адрес папки WebDAV и логин.
- `allowBackup="false"`: системное резервное копирование не уносит данные приложения.
- Резервная копия `.ldbackup` пароли и cookie не содержит (список ключей `BackupFormat.KV_KEYS` закрытый).
- Файл синхронизации шифруется на устройстве до отправки (PBKDF2-HMAC-SHA256, 600 000 итераций, AES-256-GCM; заголовок
  входит в дополнительные данные GCM). Своей криптографии нет.
- Ошибка расшифровки значения в Keystore (ключ пересоздан) стирает значение, а не падает.

### Сеть

Все запросы страниц, OPDS, картинок, `robots.txt` идут через `WebHttp`; проверки находятся там и в `NetSafety`.

- **Исправлено (1–3).** `WebHttp` вручную ведёт перенаправления (до 10). Каждый переход проверяет `NetSafety.checkRedirect`:
  с публичного хоста нельзя уйти на loopback, link-local (`169.254.0.0/16`), частные сети RFC 1918, CGNAT
  (`100.64.0.0/10`), `.local`/`.localhost`/`.internal`, IPv6 `::1`, `fc00::/7`, `fe80::/10` и IPv4-mapped; распознаются
  обходные записи адреса (целое число, `0x7f000001`, восьмеричные части, `127.1`). Переход `https` → `http`
  на публичный хост запрещён. `Authorization`/`Proxy-Authorization` не передаются другому хосту. Cookie и раньше
  привязаны к хосту (`CookieJar`).
- Адрес, который пользователь ввёл **сам** (каталог OPDS на NAS, WebDAV в локальной сети), открывается как есть:
  проверяются только переходы с публичного хоста. Это осознанно — иначе домашние серверы Calibre/Nextcloud не работают.
- **Исправлено (4).** `WebDavTransport` отказывается отправлять пароль по `http://`, если сервер не во внутренней
  сети, и принимает только `http(s)`. Сообщение об ошибке просит использовать `https://`.
- Таймауты: 20 с на соединение и чтение (`RawRequest.timeoutMs`). Пределы размера ответа есть у каждого вызова
  (страница 12 МБ, картинка 8 МБ, лента OPDS 6 МБ, `robots.txt` 512 КБ, скачивание 150 МБ, WebDAV 64 МБ);
  чтение обрывается, как только предел превышен (`ResponseTooLargeException`), не после загрузки всего ответа.
- Схемы: `file:`, `javascript:`, `ftp:` отбрасываются в OPDS и `requireHttp`. Глубокие ссылки `localdoc://` выполняют
  только четыре фиксированных действия без параметров.
- Обновления: только `https`, подпись APK проверяет система Android (постоянный ключ), поверх версии с другим ключом
  установка невозможна.
- **Открыто (10).** Проверка идёт по имени хоста, а не по IP после разрешения DNS: злонамеренный домен с A-записью во
  внутренней сети пройдёт. Полная защита требует резолва на уровне платформенного клиента (`RawHttp`) и проверки
  адреса соединения; не сделано, потому что нужна проверка на устройстве. Практический ущерб ограничен: приложение
  не показывает ответы внутренних служб иначе, чем как текст страницы самому пользователю.
- **Открыто (15).** На `targetSdk 35` Android запрещает открытый http по умолчанию (`usesCleartextTraffic` не включён),
  iOS — через ATS. Поэтому исключение «http допустим в домашней сети» в `WebDavTransport` и `NetSafety` сейчас на практике
  не действует: каталог Calibre по `http://192.168…` не откроется. Это безопасно, но неудобно; решение — `network_security_config`
  только с нужными доменами или инструкция включить https на NAS. Требует проверки на устройстве.

### Разбор чужих файлов

- **ZIP** (EPUB, FB2.ZIP, DOCX, ODT, Pages, CBZ, резервные копии): распаковка идёт только в память, на диск архив
  не извлекается, поэтому *zip-slip* невозможен; имена из архива используются как ключи, а пути для записи (резервная
  копия) отдельно проверяются `BackupFormat.isSafePath`. Лимиты: запись ≤ 64 МБ, весь архив ≤ 512 МБ, `inflateRaw`
  обрывает распаковку на заявленном размере (zip-бомба). **Исправлено (5):** любые повреждения заголовков —
  `IllegalArgumentException`; число записей сверяется с размером каталога; для Stored-записей `size == compressedSize`;
  хранимые записи входят в общий лимит. Случайный fuzz-тест на 1500 испорченных заголовках.
- **TAR** (голоса): пути с `..` и абсолютные отклоняются, ссылки и устройства пропускаются. **Исправлено (6):**
  суммарный предел 2 ГБ, проверяется по заявленному размеру до записи.
- **XML/HTML**: разбор через Ksoup; внешние сущности не загружаются, вложенность 500 тегов и 20 000 скобок RTF
  проверена тестами 1.7.5 (`RobustnessTest`).
- **Картинки**: > 60 Мпикс и повреждённые данные дают `null`, декодирование с `inSampleSize`; суммарный предел картинок
  книги 256 МБ (CBZ), страница ≤ 16 МБ.
- **Mobi/PDF/CBZ**: циклы ограничены размером данных; случайные повреждения всех экспортируемых форматов разбираются
  без зависаний (`RobustnessTest`). PDF рендерится платформенными `PdfRenderer`/PDFKit.
- **Открыто (11).** `FileAccess.readBytes` (Android) читает входной файл целиком; файл в гигабайты завершится
  `OutOfMemoryError`, который поймает верхний уровень импорта как «ошибка». Перевод на потоковое чтение с лимитом —
  в ROADMAP.

### Резервная копия и синхронизация

- Восстановление сначала проверяет файл целиком (формат, версия, JSON, полноту книг), только потом пишет. Имена файлов
  допускаются в виде простых имён, `pdf/имя` и `fonts/имя`; `..` и вложенные пути запрещены; идентификаторы книг
  проверяются тем же правилом. Ключи настроек — только из белого списка.
- Синхронизация: облако видит только шифртекст; подмена заголовка или числа итераций замечается GCM.
- **Принято (12).** Файл `.ldbackup` не шифруется: это обычный ZIP, который пользователь сам сохраняет туда, куда решил.
  Содержимое — его собственные книги и заметки, секретов нет. Шифрование копии паролем — возможное развитие.

### Права и компоненты в манифесте

- Экспортирована одна активность (`MainActivity`); служба плеера, провайдер обновлений и приёмник виджета — `exported="false"`.
- **Исправлено (7).** У фильтра открытия файлов убрана категория `BROWSABLE`. Проводники и «Поделиться» работают,
  ссылка из браузера на `file://` — нет. Проверяется `ManifestSecurityTest`.
- **Принято (8).** `MANAGE_EXTERNAL_STORAGE` нужен для функции «каталог всего устройства». Права выдаёт сам пользователь в
  настройках; без него остаются выбор файлов через системное окно и сканирование выбранной папки. Для Google Play
  потребуется декларация; для APK из GitHub Releases — нет.
- **Принято (9).** `REQUEST_INSTALL_PACKAGES` — самообновление; установку подтверждает пользователь в системном окне.
- `RECORD_AUDIO` — только для голосового управления, выключенного по умолчанию; запрашивается при включении.

## Что не проверено

- iOS: ATS в `Info.plist` не содержит `NSAllowsArbitraryLoads`; реализации Keychain и `NSURLSession` прочитаны, но не запускались.
- Поведение `HttpURLConnection` и `NSURLSession` на реальных перенаправлениях и сертификатах (закреплений сертификатов нет).
- R8-обфускация отключена; включение требует правил для сериализуемых классов и проверки релизной сборки.
