# Системные инструкции для AI-агента (LocalDoc AI — KMP)

## Архитектурные правила

1. **Строгая изоляция платформенного кода.** В `commonMain` пишется только чистый Kotlin,
   бизнес-логика (`SmartPipeline`) и UI (`Compose Multiplatform`). Любые системные вызовы
   оформляются через `expect/actual`.
2. **Безопасность памяти в C++ (`cpp_core/`).**
   - Запрещено использовать сырые указатели без проверки на `nullptr`.
   - Вся работа с `llama.cpp` идёт строго через чистый C-интерфейс (`localdoc_c_api.h`),
     чтобы iOS `cinterop` и Android JNI вызывали одни и те же функции без дублирования.
3. **Кроссплатформенный RAG.** Не использовать платформо-специфичные БД (ObjectBox и т.п.)
   в общих модулях. Векторное хранилище — `VectorStore` (JSON + KeyValueStore) с
   L2-нормализацией и косинусным поиском; интерфейс `EmbeddingProvider` совместим
   с будущей ONNX-моделью эмбеддингов.
4. **Синхронизация с llama.h.** Сабмодуль `cpp_core/llama.cpp` пиннут на тег `b10004`.
   Перед изменением сигнатур C-кода сверяться с `cpp_core/llama.cpp/include/llama.h`.

## Стиль кода

- Kotlin: строгая типизация, корутины (`Flow`) для стриминга, никаких блокирующих вызовов
  на главном потоке (`Dispatchers.IO` для файлов, сети и инференса).
- C++: стандарт C++17, аккуратное управление KV-кэшем llama.cpp, обязательное освобождение
  всех ресурсов (`localdoc_free`), атомарные флаги отмены генерации.
- UTF-8: в C-мосте токены отдаются в UI только завершёнными UTF-8 последовательностями
  (критично для кириллицы).
- Коммиты: короткие по смыслу, каждый шаг = один коммит; структуру папок не нарушать.

## Проверка сборки

- Android: `./gradlew :composeApp:assembleDebug` (нужны Android SDK + NDK).
- iOS: `./cpp_core/scripts/build_ios_xcframework.sh` и
  `./gradlew :composeApp:linkDebugFrameworkIosSimulatorArm64` (macOS + Xcode).
